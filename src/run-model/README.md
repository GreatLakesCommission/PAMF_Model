# RUN-MODEL  

Scripts and functions that pertain to:  

  * updating the transition matrices   
  * updating the partial controllability matrix   
  * running the optimization   

Also contains:  

  * Initial inputs into the 2018 model and the scripts that generated them. 
    These are the starting points for the transition matrices, the partial 
    controllability matrix, etc.  
  * Information about which management combinations are available under 
    different restrictions (e.g., if water depth can't be controlled, FLOOD is
    not a useful recommendation)  

>:memo: NOTE: To understand how these scripts work together, look at run-the-model.R first 

# DIRECTORIES

- :file_folder: [generators](/src/run-model/generators/)  
Contains code that generates the initial versions of several model inputs (found
in the initial-inputs and definitions subdirectories), including:  

  * Transition matrices             (initial-inputs)  
  * Reward matrix                   (initial-inputs)  
  * Partial controllability matrix  (initial-inputs)  
  * Policy definitions              

- :file_folder: [initial-inputs](/src/run-model/initial-inputs/)   
Inputs for the initial (2018) model run (when there was no prior-year data to 
update from)  

- :file_folder: [test-cases](/src/run-model/test-cases/)   
Contains test data and descriptions of expected behavior for:  

   * transition matrix update

## FILES  

- [build-reward-matrix.R](/src/run-model/build-reward-matrix.R)  
Builds a matrix that holds reward values for each state, based on the following 
information:  

  - cost (empirical or a priori)  
  - satisfaction (expert elicited values)  

- [file-io-special-cases.R](/src/run-model/file-io-special-cases.R)  
The details of many of the file reads/writes depend upon both the file and the 
year it was generated. E.g., varying amounts of formatting go into reading files
that were generated by earlier versions of the model.  
Instead making the whole model run script look like a sequence of messy file I/O,
we've put all of the special cases in here.  

- [optimizer.R](/src/run-model/optimizer.R)  
Generate optimal and near-optimal policies for management unit states under each policy 
restriction.  

- [optimizer-functions.R](/src/run-model/optimizer-functions.R)  
Functions supporting optimizer.R.  

- [pc-update-functions.R](/src/run-model/pc-update-functions.R)  
Functions supporting [update-pc.R](/src/run-model/update-pc.R).  

- [policy2guidance.R](/src/run-model/policy2guidance.R)  
Script that assigns optimal and near-optimal management combinations to 
management units, depending on their current state and restrictions.  

- [suboptimal-functions.R](/src/run-model/suboptimal-functions.R)  
Functions supporting [optimizer.R](/src/run-model/optimizer.R).  

- [run-the-model.R](/src/run-model/run-the-model.R)  
A controller script that handles file I/O and calls the different scripts that 
make up the model's operations.  

- [transition-update-functions.R](/src/run-model/transition-update-functions.R)  
Functions supporting [update-transitions.R](/src/run-model/update-transitions.R).    

- [update-pc.R](/src/run-model/update-pc.R)  
Script that updates partial controllability using the same methodology as the 
transition matrix update.  

- [update-transitions.R](/src/run-model/update-transitions.R)  
Script that uses data packages to update the model's transition probabilities.
