## Overview  

### What are base runs?  

Base runs are model runs that were created after that year's 'OFFICIAL' run, in
order to accommodate updates to the data cleaning code, as well as any changes
to the transition / partial compatibility update methods. An 'OFFICIAL' run
results in guidance that is distributed to PAMF participants.  

All model runs from 2020 or later contain base runs in their update stem.  

For example,  
 
* the 2020 OFFICIAL run was built off of the base runs generated in 2020    
* the 2021 OFFICIAL run was built off of the base runs generated in 2021    
* the 2022 OFFICIAL run was built off of the base runs generated in 2022,   
* the 2023 OFFICIAL run was built off of the base runs generated in 2023,
* the 2024 OFFICIAL run was built off the official run for 2023, and
* the 2025 OFFICIAL run was built off of the base runs generated in 2025. 

Please note that you DO NOT have to generate a new set of base runs every year!
This only becomes necessary when you make changes to the parts of the code 
mentioned above.  

### Why do they exist?   

Each time we update the data cleaning algorithms to change the structure of one
or more cumulative output files, it's necessary to create a new set of base runs
with the new outputs. Otherwise, outputs from new runs won't append to the
cumulative files. 

In addition, base runs can be used to re-run the model to incorporate updates 
to previously entered data. For example, if we find out that a report from 
2021 that was previously part of valid data package was actually not (e.g., someone 
managed when they reported a rest action) then base runs can be used to incorporate 
this new info into the model.

Additionally, changes to the data cleaning algorithms may have downstream
effects on the transition and partial controllability matrices (via the
inclusion/exclusion of different sets of data packages). Using the most recent
base run as the prior for the next OFFICIAL run ensures that the entire history
of updates in these matrices is generated by the same set of data cleaning
rules.  

Changes to the transition and partial controllability matrix priors, as well as
to the methods for updating those matrices, also create a situation where base
runs are needed. If base runs are not created after such changes, then (a) new
priors are not incorporated, and/or (b) posteriors are generated by a mix of
different methods (the old methods in earlier years and the new method in later
years). This DOES affect the current posterior in any given cycle because all
posteriors are updates of the ones that came before.  

### How do they differ from OFFICIAL runs?  

Base runs may have different transition and partial controllability histories
than the corresponding OFFICIAL run from the same year. Consequently, downstream
outputs like **policies.csv** and **guidance.csv** may also differ. Note that
the guidance generated by base runs is NOT posted to the Web Hub.  

## Building New Base Runs  

Build a new set of base runs (2018 through the year of the last OFFICIAL run) 
whenever you've modified the code to change the structure of any of the cumulative
outputs and/or the matrix updating algorithms. See the last section in this 
document for instructions.  

### How to use them  

If you have changed the structure of any of the cumulative outputs or the matrix
updating methods since the last OFFICIAL run, you'll build your next OFFICIAL
run off of your new set of base runs rather than off of the previous OFFICIAL
run.  

When you do this,
1. Choose the base run for the year prior to your current cycle as the 'previous 
   run.'
   
2. Close the program once the check box screen populates.

3. Copy the dated guidance from all previous OFFICIAL runs into the new model run
   directory. 

  * As of 2025, these files are:  

	  - guidance-2018-10-05.csv  
	  - guidance-2018-08-22.csv  
	  - guidance-2020-09-15.csv  
	  - guidance-2021-08-25.csv    
	  - guidance-2022-08-23.csv  
	  - guidance-2023-08-15.csv
	  - guidance-2024-08-21.csv
	  
	 This will ensure that the partial controllability updates will 
   be based on guidance that the participants actually saw, and that your 
   cumulative guidance file will contain correct information.
   
  If you're following these instructions, you'll also have to create this file
  in the directory of your previous OFFICIAL run. Simply add the date to the
  name of the annual (not the cumulative) guidance file.  
   
> :warning: **CAUTION** If you see the following warning in the console, your outputs do not 
   contain the official guidance for one or more years. Double check your files.
>
> **Warning:** readPreUpdateGuidance: Guidance released in [YEAR] is not in 
        [RUNPATH]. Using the guidance from the your selected previous run.
        Updated guidance may not reflect PAMF history. 

4. Continue the model run as usual.  

### How to build new base runs  

When you build base runs, you'll re-run the model for all cycles from 2018 
through the most recent completed cycle.  

1. Create a new model run for 2018, using files from the 2018 data pull.
  * Use the enrollFULL file for enrollment (also true for 2019 but not later base runs)
  
2. Exit the model once the check box screen populates.

3. Copy the following files into the model run directory that you just created:
	
  * From the most recently completed base 2018 run:  
    - monitor-issues.csv  
    - manage-issues.csv  
    - datpak-compare.xlsx  
    - README RUN NOTES.txt  
    - Reports_reviewed_2018....docx
       
  * The monitor- and manage- issues files contain checkbox entry information: 
  copying them means that you don't have to fill out the checkbox interface.
  This saves you a lot of time and prevents errors. If you've changed the 
  structure of these outputs, however, you'll have to modify the .csv files to 
  reflect the new structure.  
  
	* datpak-compare and README RUN NOTES describe differences between the current 
	base run, it's predecessors (if any) and the OFFICIAL run that generated the 
	guidance that participants used.   
	
	* Reports_Reviewed is a record of the human side of the data cleaning process.   
	
4. Re-open the model and resume the run.

5. Create a base run from 2019, using files from the 2019 data pull, and using the
   2018 base run you just created as the 'previous run'.
   
6. Exit the PAMF model once the form populates.

7. Copy files from the most recent completed base 2019 run into the model run
   directory that you just created:
   
	* All analogous files to those described above  
	* guidance-2018-10-05.csv  
    - guidance-2018-10-05.csv contains the actual guidance that was released in 
    2018. It's important to incorporate this for two reasons:  
	    1. to ensure that the partial controllability matrix is updated based on the
           guidance that participants saw & responded to  
	    2. to populate the cumulative guidance output  
	
8. Re-open the model and resume the run.  
> :warning: If you see the following warning in the console, check your 2018 guidance file 
   and try again:  
   
>   Warning: readPreUpdateGuidance: Guidance released in [YEAR] is not in 
        [RUNPATH]. Using the guidance from the your selected previous run.
        Updated guidance may not reflect PAMF history.

9. Create the 2020 base run in the same way, making sure to copy ALL dated 
guidance files into your new directory.  
    
10. Etc.  


## Updating The Model  

If you are updating the model in a way that changes the way reports are moved
into cycles, updating the transition matrices, or updating the partial
controllability matrices, then you will need to account for guidance created by
the official model runs, not the base runs. To do this, you will need to update
the list of guidance files ("GUIDANCE_FILES") in global-constants.R to read in the official 
guidance produced for each cycle that needs a base run (the guidance that was 
distributed to participants). **Do not** update the list unless you need to run 
base runs.
